# AGENTS.md — working on SnapDraw

Handoff for coding agents working on **SnapDraw**, a production Chrome Manifest V3 extension that
captures the visible viewport, annotates it with an embedded Excalidraw canvas, and records tab or
whole-screen video. SnapDraw is **local-only**: screenshots, recordings, annotations and settings
never leave the machine; no backend, analytics, CDN or remote font.
Start with [README.md](README.md) and [ARCHITECTURE.md](ARCHITECTURE.md), then this file.

## What this repo is

- **Stack:** React 18.3.1, TypeScript 5.9 (strict), Vite 8 (Rolldown), Excalidraw 0.18.1, Vitest 5,
  Chrome MV3 (Chrome 116+; E2E needs Chrome 137+).
- **Surfaces:** popup, background service worker, screenshot editor tab, video editor tab, hidden
  offscreen recorder document, compact screen-share recorder window.
- **Data & build:** one IndexedDB database (`snapdraw`, store `screenshots`) is shared by the worker
  and all extension pages; `npm run build` → `dist/`, loaded unpacked. The manifest `key` fixes the
  extension ID (currently `gdjakoleacfjjgbhbhfdjijkhpmiifhf`).

## Non-negotiables

**Local-only, always.** No `fetch`/XHR/WebSocket/remote URL in `src/` or `public/` (except SnapDraw's
own repo/issues links in `src/editor/links.ts`), no analytics, telemetry, accounts, uploads or CDN
assets. Fonts are copied into `public/fonts` at build time and `public/excalidraw-asset-path.js`
points Excalidraw at them. Extension pages use a strict `'self'`-only CSP in `public/manifest.json`.

**Permissions stay exactly:** `activeTab`, `clipboardWrite`, `offscreen`, `tabCapture` — no
`host_permissions`, no `content_scripts`. `scripts/validate-build.mjs` and `tests/manifest.test.ts`
fail on additions; never weaken them or the CSP directives.

**Never change the manifest `key`** unless you intend to change the extension ID. Shortcuts, clipboard
grants and stored IndexedDB history are tied to the ID.

**Keep generated files generated.** `dist/` (build output), `public/fonts/` (from `copy-fonts.mjs`),
`test-results/` (E2E artifacts), `.sandbox/` and `.tmp-*/` are gitignored. `docs/screenshots/*.png` are
tracked but regenerated by `scripts/e2e.mjs` — never hand-edit them.

**Don't upgrade Excalidraw casually.** The menu API, CSS hooks, undo/redo workaround, font asset path,
colour handling and canvas readback shim all target 0.18.1; an upgrade is a feature with its own
verification pass.

## First-run setup

Prerequisites: **Node.js 22.12+**, npm 10+ (Vite 8), **Chrome 116+** to run the extension, **Chrome
137+** (or Chromium / Chrome for Testing) for E2E.

```powershell
npm install
node scripts/copy-fonts.mjs
node node_modules/typescript/bin/tsc --noEmit
node node_modules/vite/bin/vite.js build
node scripts/validate-build.mjs
```

Open `chrome://extensions`, enable **Developer mode**, **Load unpacked** → select the **`dist/`**
folder (the one containing `manifest.json`), pin SnapDraw. **After every build, reload the extension**
there (reload icon or `Ctrl+R` on that page) and reopen extension tabs — a stale worker/bundle is the
most common "my change didn't apply".

## Commands & Windows quirks

**npm.ps1 is blocked by execution policy.** Use `cmd /c npm …` or call the tools directly:

```powershell
cmd /c npm run build
node node_modules/typescript/bin/tsc --noEmit
node node_modules/vitest/vitest.mjs run
node scripts/e2e.mjs
```

**Full build** is the First-run sequence in order: `copy-fonts.mjs` → `tsc --noEmit` → `vite build` →
`validate-build.mjs`. Run each as `node <path>` (or `cmd /c npm run build`).

**`spawn EPERM` / `net use` during Vite build.** Vite's Windows config real-path probe can be blocked
by the sandbox. The workspace has a local gitignored shim; use it for the build:

```powershell
$env:NODE_OPTIONS = "--require $PWD\.sandbox\no-spawn.cjs"
node node_modules/vite/bin/vite.js build
Remove-Item Env:NODE_OPTIONS
```

If `.sandbox/` is missing (fresh clone), build unsandboxed or try the README fallback `node node_modules/vite/bin/vite.js build --configLoader native`.

**PowerShell corrupts UTF-8.** Windows PowerShell 5.1 `Get-Content`/`Set-Content` and `>` default to
ANSI/UTF-16, and the sources use typographic characters (en dashes in user copy and docs). Never
rewrite sources through PowerShell text cmdlets — use the `edit`/`write` tools or a Node UTF-8 script.
`.gitattributes` normalises line endings to LF.

**Chrome needs a wider sandbox.** Chrome cannot launch under the default agent sandbox (crashpad
`OpenProcess: Access is denied`); E2E, headed scripts and `chrome://extensions` verification need
**danger-full-access / unsandboxed**. Don't try to disable crashpad.

**Headless Chrome cannot capture.** It cannot create real `tabCapture`/`getDisplayMedia` streams, so
`scripts/e2e.mjs` seeds a WebM fixture and validates the downstream pipeline; real capture is checked
with the gitignored headed scripts in `.sandbox/` (`headed-rec.mjs`, `headed-screen.mjs`,
`headed-desktop.mjs`, `headed-audio.mjs`).

**Caches/extension data follow the extension ID.** Rebuilding is safe; changing/removing the `key` or
moving the unpacked folder can change the ID and empty history. The current ID is in
`.sandbox/extension-id.txt`. Dev loop: `node node_modules/vite/bin/vite.js build --watch --mode
development` (or `npm run dev`), then reload the extension; `npm run preview` is UI-only.

## Architecture in 60 seconds

- The **popup** messages the **service worker**; the worker captures the visible tab, writes a `Blob`
  + thumbnail to **IndexedDB**, then opens `src/editor/editor.html?session=<uuid>`.
- The **editor tab** loads the record (and keeps it), builds one locked Excalidraw image element, and
  exports a white-background PNG via `exportToBlob`. Refreshing is safe.
- **"This tab" recording:** popup obtains a `tabCapture` stream id, the worker creates a hidden
  **offscreen document** that owns `MediaRecorder`; recording continues after the popup closes.
- **"Whole screen" recording:** the popup opens a small visible **recorder window** that answers
  Chrome's `getDisplayMedia` picker and records there.
- Both paths save a WebM (`kind: "video"`) and open `src/video/video.html?session=<uuid>`, where a
  transparent Excalidraw overlay sits exactly on the video rectangle; export composites video +
  annotations in real time.
- The `REC` badge and recording lifecycle are owned by the service worker. Full diagrams and contracts
  live in [ARCHITECTURE.md](ARCHITECTURE.md).

## Core flows

1. **Screenshot:** popup button or `capture-screenshot` command → `captureVisibleViewport()`
   (`src/services/screenshot.service.ts`) → `chrome.tabs.captureVisibleTab` → size guard
   (`MAX_CAPTURE_EDGE = 8192`) → `putScreenshot()` → editor tab. `classifyTabUrl()` rejects protected
   pages before capture.
2. **Tab recording:** `getTabCaptureStreamId()` (`src/services/recording.service.ts`) →
   `RECORDING_START` → offscreen document → explicit tab constraints → `MediaRecorder` (4 Mbps,
   250 ms timeslice) → `saveRecording()`.
3. **Whole-screen recording:** popup → `chrome.windows.create({ type: "popup", 460×400 })` →
   `recorder.ts` → `getDisplayMedia` → `MediaRecorder` → `saveRecording()` → worker event opens the
   video editor.
4. **PNG export:** `src/services/export.service.ts` — scale 1, 16 px padding, white background,
   `exportWithDarkMode: false`; clipboard or download.
5. **Annotated video export:** `src/services/video-export.service.ts` — draw each frame + the Excalidraw
   static canvas at intrinsic resolution, `canvas.captureStream(30)` + `MediaRecorder` + Web Audio;
   takes as long as the recording.

## Testing

**Unit tests:** `node node_modules/vitest/vitest.mjs run` — nine suites in `tests/*.test.ts`, **180
tests** at the time of writing. Node environment, no Chrome, no network, `fake-indexeddb`. The
`createRequire` in `vitest.config.ts` avoids a Windows config-loading probe; don't "simplify" it.
Suites cover storage/retention, image + video helpers, messaging, manifest invariants, capture/export/
recording services and the canvas readback shim.

**E2E:** build `dist/` first, then `node scripts/e2e.mjs` (options `--headed --keep
--chrome="C:\path\to\chrome.exe"`). Requires Chrome 137+; installs the unpacked extension via the CDP
`Extensions` domain (branded Chrome 137+ ignores `--load-extension`). Drives real input, clipboard and
downloads, serves local fixtures on `127.0.0.1`, asserts zero external requests, regenerates
`docs/screenshots/*.png`. Size: **115 checks** at the time of writing (the generated
`test-results/e2e-report.json` is authoritative — trust it and the console summary over prose counts).
Artifacts: `test-results/e2e-report.json`, `test-results/export-*.png`,
`test-results/annotated-video.webm`, `docs/screenshots/*.png`. The harness adds `host_permissions` +
`tabs` to a **temp copy** only — never in `public/manifest.json`.

**Headed verification:** headless can't start real capture streams, so when touching recording/service
worker run a local script against a fresh `dist/` in unsandboxed headed Chrome:

```powershell
node .sandbox/headed-rec.mjs       # real "This tab" recording -> video editor
node .sandbox/headed-screen.mjs    # whole-screen recording via the recorder window
node .sandbox/headed-desktop.mjs   # desktopCapture picker variant / isolation
node .sandbox/headed-audio.mjs     # tab-audio constraint variants in an offscreen document
```

Logs sit next to the scripts; both are gitignored. If `.sandbox/` doesn't exist, verify manually.

## Pitfalls & caveats

### 1. Tab audio and the offscreen document

- **Do:** request audio with explicit constraints in `src/offscreen/offscreen.ts`:
  `{ mandatory: { chromeMediaSource: "tab", chromeMediaSourceId: streamId } }`.
- **Don't:** use bare `audio: true` there. Chrome tries to show a microphone prompt an offscreen page
  can't display, crashing the renderer ("SnapDraw has crashed").
- Fall back to `audio: false` (video-only) if audio negotiation fails; don't fail the recording.
- `chrome.tabCapture.getMediaStreamId` needs the popup's user gesture — recording can't start from the
  keyboard command.

### 2. Offscreen lifecycle and badge ownership

- The service worker owns the `REC` badge and the offscreen document (`ensureOffscreenDocument` with
  `reasons: ["USER_MEDIA"]`, `closeOffscreenSafely`, `sendToOffscreen` timeouts). Never set the badge
  from a page.
- Always clean up on failure: failed start closes the document and clears the badge.
- If the recorded tab closes, the offscreen document finalises and emits `recording:saved`; the worker
  opens the video editor — keep that path working.
- Closing the browser discards an in-progress recording (nothing is persisted until stop/save).

### 3. Whole-screen recording uses a visible window

- Chrome's `getDisplayMedia` picker requires a visible extension page, and a `desktopCapture` stream
  id can't be consumed by the hidden offscreen document. The flow is intentionally popup →
  `chrome.windows.create({ type: "popup" })` on `src/recorder/recorder.html` → `getDisplayMedia`.
- The recorder window is a window, not a tab, and closes itself after save/cancel.
- Don't add a "symmetric" `chrome.desktopCapture` offscreen path; the `.sandbox/` experiments document
  why it fails.

### 4. Excalidraw 0.18.1 quirks

- No imperative `undo()`/`redo()`: header buttons synthesise `Ctrl/Cmd+Z` / `Shift+Ctrl/Cmd+Z` keydown
  events on the `.excalidraw` container inside the workspace (`src/editor/excalidrawActions.ts`), never
  on `document`.
- The `theme` prop controls both Excalidraw's UI and canvas rendering (`src/editor/useColorScheme.ts`).
- `UIOptions.canvasActions` disables Excalidraw's own export/load/save/clear actions; SnapDraw's header
  is the single source of truth.
- Initial scene uses `convertToExcalidrawElements` (`src/editor/EditorCanvas.tsx`): one image at
  natural pixel size, then `scrollToContent(..., { fitToContent: true })`.
- Help/library entry points are hidden in `src/editor/editor.css`; the `?` help dialog is suppressed in
  `src/editor/Editor.tsx`; the custom `MainMenu` replaces Excalidraw's external links. Before any
  upgrade re-check: font asset path, menu API, CSS class hooks, undo/redo dispatch, `exportToBlob`
  options, dark-theme filter behaviour, readback shim.

### 5. Colour fidelity: SVG wrapper + disabled dark filter

- `wrapImageDataUrlInSvgDataUrl()` (`src/utils/image-conversion.ts`, used by
  `src/editor/EditorCanvas.tsx`) stores the capture as an SVG data URL because Excalidraw
  counter-inverts raster image elements in dark theme (not colour-neutral); SVG is exempt.
- The dark canvas CSS filter is intentionally disabled in `src/editor/editor.css` and
  `src/video/video.css` so editor and export agree.
- Export always uses a white background with `exportWithDarkMode: false`
  (`src/services/export.service.ts`); `viewBackgroundColor` stays transparent in the scene.
- **Don't** revert to a raw PNG data URL, re-enable the filter, or change the export background — that
  reintroduces the colour shift. E2E asserts the fixture's yellow/magenta pixels survive in the
  dark-mode editor screenshot, so a colour regression fails the suite.

### 6. Canvas readback shim

- `src/utils/canvas-readback.ts` patches `getImageData` on `src/editor/main.tsx` and `src/video/main.tsx`
  pages. Excalidraw's eyedropper reads 1×1 px from `.excalidraw__canvas` without `willReadFrequently`,
  which triggers Chrome's Canvas2D advisory on every pointer move.
- The shim routes reads whose area is ≤ `SHIM_MAX_READ_AREA` (64 device pixels) through a scratch
  `willReadFrequently` canvas and falls through otherwise. Keep the predicate in sync on Excalidraw
  upgrades; tests: `tests/canvas-readback.test.ts`.

### 7. Screenshot persistence and retention

- The editor never deletes the record on load; refreshing/reopening `?session=…` works and history can
  reopen captures.
- `HISTORY_LIMIT = 20` and `HISTORY_RETENTION_MS = 30 days` in `src/services/storage.service.ts`;
  pruning runs on install/startup and after captures/recordings.
- History listing stays metadata + thumbnail only (no full blobs). Legacy rows are healed by
  `ensureThumbnailFor()`, which persists the thumbnail.
- The only delete-on-failure case is a failed editor-tab open (`discardStoredScreenshot`) — keep it so
  orphans can't accumulate.

### 8. Protected pages and capture limits

- `classifyTabUrl()` (`src/services/screenshot.service.ts`) rejects `chrome://`, `chrome-untrusted://`,
  `chrome-search://`, `chrome-error://`, `edge://`, `brave://`, `about:`, `view-source:`, DevTools, the
  Chrome Web Store and other extension pages, with friendly copy.
- `MAX_CAPTURE_EDGE = 8192` per side for captures; 16,384 px per side for PNG export
  (`src/services/export.service.ts`). Keep both guards.
- Never surface raw Chrome errors; map them through `toErrorPayload()`/`errorPayload()` to get
  `code` + `message` (+ optional `hint`).

### 9. E2E temp-manifest exception

- `scripts/e2e.mjs` and `.sandbox/headed-*.mjs` add `host_permissions` + `tabs` to a **temporary copy**
  of `dist/` because automation has no toolbar gesture to grant `activeTab`.
- Never copy that into `public/manifest.json`; validation and `tests/manifest.test.ts` must catch it.

### 10. Video export

- Export is real time by design (audio sync): keep the foreground-tab requirement and don't promise a
  naive faster path without reworking audio.
- Composite `canvas.excalidraw__canvas.static` (annotations only), not the interactive canvas, and keep
  the CSS filter off — canvas capture reads raw pixels.
- The audio graph is cached per `<video>` in a `WeakMap` (one `MediaElementAudioSourceNode` per element)
  and disposed via `disposeVideoExportAudio` on unmount. Don't close the `AudioContext` after each
  export or the second export is silent.
- Chrome reports `duration === Infinity` for many MediaRecorder WebM files; use the stored `durationMs`
  fallback. Cancel must keep annotations and restore playback state.

### 11. Build, fonts, asset path

- `public/fonts` is generated/gitignored and `copy-fonts.mjs` skips when populated; remove the folder
  and rebuild if fonts look stale.
- `public/excalidraw-asset-path.js` must stay a classic script loaded **before** the module bundle in
  the HTML pages (it sets `window.EXCALIDRAW_ASSET_PATH` and rewrites CDN fallbacks).
- `npm run icons` regenerates `public/icons/*.png` from code; don't hand-edit the PNGs.

### 12. Windows/agent environment

- `npm.ps1` blocked → `cmd /c npm …` or direct Node binaries. Vite `spawn EPERM`/`net use` →
  `.sandbox/no-spawn.cjs` or build unsandboxed. Chrome won't start under the default sandbox →
  Chrome work needs danger-full-access. PowerShell text cmdlets corrupt UTF-8 → use the editor
  tools or a Node UTF-8 script. After every build: reload the extension.
